# 智能发票解析归档 Web App 开发需求文档 (V1.0)

## 1. 项目概述
本项目是一个基于 Vue 3 开发的**纯前端、无后端**个人财务管理工具。旨在解决扫描件（多页 PDF/图片）中发票混杂的问题。通过浏览器直接读取 iCloud 文件夹，利用 **Gemini 2.5 flash lite API** 或者 **Gemini 3 flash preview API** 的多模态能力进行语义识别，实现自动拆分、精准提取、自动重命名及 Excel 报表汇总。

* **核心目标**：数据零落地、隐私安全、全流程自动化。
* **适用平台**：PC/Mac 浏览器、iOS Safari (支持 PWA 模式)。

---

## 2. 技术架构与库选型
* **前端框架**: Vue 3 (Vite) + Tailwind CSS + Element Plus。
* **PDF 解析/预览**: `pdf.js` (渲染缩略图至 Canvas)。
* **PDF 物理操作**: `pdf-lib` (在内存中执行页面的提取、合并与保存)。
* **AI 逻辑**: `@google/generative-ai` (Gemini API 官方 SDK)。
* **拖拽交互**: `SortableJS` (处理页面顺序调整)。
* **文件导出**: `JSZip` (生成 ZIP 包) + `xlsx` (SheetJS，生成 Excel 报表)。

## 3. 核心功能与逻辑流

### 3.1 初始设置 (Settings)
* **API Key 存储**: 提供 API Key 输入框，持久化存储于浏览器 `localStorage`。
* **多组API Key 轮替**: 允许用户输入多个 API Key，多个 API Key之间用逗号分隔，系统会自动轮替使用。
* **默认提示词**: 提供一个默认的 Prompt 模板，用户可以**修改发给 Gemini 的 Prompt 模板**。
默认提示词：
```
你是一个专业的跨国财务审计与数据提取专家。
请仔细分析我提供的发票文件（图片或PDF），并严格按照以下规则提取信息。

【提取字段与处理规则】
1. company_name (公司名称): 提取开具发票的销售方主体名称。必须去除多余的空格和换行符。
2. date (发票日期): 统一格式化为 "YYYY-MM-DD"。如果原日期是其他格式（如 DD/MM/YYYY 或拼写出的月份），请务必转换。
3. invoice_no (发票号): 完整保留原文的发票号码，包括任何字母前缀和连字符（如 FR-2024-001），不可擅自改写或缩减。
4. purpose (发票用途): 提取购买的商品主体名称和数量。
   - 如果原文是法语或其他外语，请准确翻译成尽量精简的中文。
   - 格式必须严格统一为：“商品名称 x数量”（例如：“木质A4夹板夹 x6”）。
   - 如果一张发票包含多个不同的商品，请用逗号将它们连接起来。
5. tva (TVA增值税): 仅提取增值税金额。只保留纯数字和对应的小数点，绝对不要带税率百分比，也不要带货币符号（例如正确格式为 "6.30"）。如果没有列出税额，请返回 "0.00"。
6. total_amount (总金额): 仅提取发票的总金额（含税金额）。只保留纯数字和对应的小数点，绝对不要带货币符号（例如正确格式为 "37.78"）。
7. currency (货币单位): 识别发票使用的货币，并返回标准的三个字母代码（如 "EUR", "USD", "CNY" 等）。

【输出格式强制要求】
- 你的回答必须且只能是一个合法的 JSON 对象。
- 绝对不要在 JSON 外面包裹任何 Markdown 标记（例如不要输出 ```json 和 ```）。
- 绝对不要输出任何额外的解释、问候或分析过程。

必须严格遵守以下 JSON 结构返回：
{
  "company_name": "",
  "date": "",
  "invoice_no": "",
  "purpose": "",
  "tva": "",
  "total_amount": "",
  "currency": ""
}
```
* **重命名规则**: 预设变量（如 `{date}_{company}_{amount}.pdf`）。

### 3.2 PDF 预处理器 (PDF Splitter) —— **核心逻辑**
处理“一个 PDF 包含多份发票”的情况：
1.  **逻辑分组机制**:
    * 系统维护一个二维数组 `groups: number[][]`。
    * 初始状态：`[[0, 1, 2...n]]`（所有页码在一个组）。
2.  **交互设计**:
    * **缝合/剪断**: 在缩略图之间提供“🔗/✂️”按钮。点击“✂️”将数组切分为两个独立子数组；点击“🔗”合并。
    * **垃圾桶**: 标记“忽略”的页码不进入最终生成名单。
    * **排序**: 支持拖拽缩略图改变页码顺序。
3.  **生成执行**: 点击确认后，`pdf-lib` 根据 `groups` 的索引从原始 Blob 中抽取页面，生成多份单发票 PDF。

### 3.3 Gemini API 语义提取
* **多模态输入**: 直接将拆分后的单份 PDF 转换为 Base64 发送。
* **数据结构**: 强制要求返回 JSON 对象，包含：`company_name`, `date`, `invoice_no`, `purpose` (法语翻中文+精简), `tva`, `total_amount`, `currency`。

## 4. 数据导出规范 (Excel 8 列规则)

最终生成的 Excel 报表必须严格遵循以下映射逻辑：

| 列号 | 字段名称 | 逻辑与示例 |
| :--- | :--- | :--- |
| **1** | 项目分类 | 默认值：`Facture(Richelieu)` |
| **2** | 公司名称 | 提取的主体名称，去除换行 |
| **3** | 发票日期 | 统一格式：`yyyy-mm-dd` |
| **4** | 发票号及用途 | 格式：`{发票号} {精简用途}` (例如：`INV123 键盘 x1`) |
| **5** | 总金额 | 仅保留数字 (例如：`88.05`) |
| **6** | 货币单位 | 如果为 `EUR` 则显示 `EUROS`；其余显示代码 |
| **7** | TVA 金额 | 仅保留数字 (例如：`14.68`) |
| **8** | **合并信息** | **直接拼接 1-7 列内容，中间以空格分隔** |

## 5. 部署与 iOS 适配

### 下一步操作建议：
1.  **分片上传**: 对于超过 10 页的大 PDF，建议先加载第一页缩略图。
2.  **错误处理**: 在 `JSON.parse` Gemini 的返回结果前，先用正则过滤掉可能存在的 Markdown 代码块标签。
3.  **安全性**: 在 EC2 部署时，确保 Nginx 的 `client_max_body_size` 足够大（建议 50M），因为高质量扫描件体积较大。
